# spec — 仕様

コードより先に、ここで「何が正しいか」を決める。CI の formal ジョブ (`scripts/formal.sh`) が全部を検査する。

| ファイル | 道具 | 何を固定するか |
|---|---|---|
| `*.tla` + `*.cfg` | TLA+ (TLC) | 状態の流れ。cfg の INVARIANT がどの状態でも成り立つこと、行き詰まらないこと |
| `*.smt2` | Z3 | 算術・条件の性質。性質の否定を置き、すべての (check-sat) が `unsat` |

決まり:
- cfg の INVARIANT ごとに、**実装** を検査するテスト `TestSpec_<名前>` を書く (PBT か全件ループで、仕様と同じ性質をコードに対して確かめる)。ないと CI が落ちる
- 振る舞いを変える PR は、先に spec を変える。spec と実装と TestSpec_ を同じ PR で
- 定数は小さく (TLC が 1 分以内に終わる範囲)。大きな範囲は PBT が受け持つ
