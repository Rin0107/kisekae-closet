# 着せ替え v2 — 仕様の考え直し (2026-11-21)

持ち主の声 (2026-11-21):「例の写真で試したけどヤバい。全くアバターにフィットしてないから全くイメージがわかない」。
要件: **アバター**・**自分の服の写真を使う**・**着せ替えてイメージを沸かせる**。
一番大事なのは**服を、人が着ているように並べて、イメージを沸かせる**こと。

この文書は今の着せ替え (`src/outfit.ts`・`src/cutout.ts`・`src/Avatar.tsx`) を直すのではなく、前提から置きかえる案。

---

## 1. なぜ今のはフィットしないか

今のやり方は「**決まった体に、どんな写真でも自動で合わせる**」。それが崩れる理由は、細かい直し (#19 #22 #26 #33 #37 #41 #44 #47) では埋まらない前提の食い違い。

| # | 食い違い | 画面で起きること |
| --- | --- | --- |
| 1 | 写真の**どこが肩で、どこが裾か**を機械が推し量っている (幅・重心・画素の主軸) | 写真が変わると肩が首に寄る・浮く・胴からずれる。直すたびに別の写真で崩れる |
| 2 | 体の姿勢 (腕を約 35° 開いた A ポーズ) に**服を合わせようとして、袖を切って回す** | 袖の付け根に継ぎ目・段差。ハンガーで垂れた袖が不自然に持ち上がる |
| 3 | 体は**写実的な 3D の人**、服は**平らな写真** | 平らな板を人の前に貼ったように見え、着ている感じが一番出ない組み合わせ |
| 4 | 大きさを**幅だけ**で決め、服同士の大きさの比べ合いがない | ズボンとトップスの丈の釣り合いが写真まかせ。コートが短く見える・シャツが長く見えるなど |
| 5 | 背景を**四辺の色からたどって**自動で消す | 白い壁の前の白シャツなどで、服の後ろに四角い背景が残る (今の見本の画面の白い四角) |
| 6 | 撮り方の手引きがない | 斜め・床置き・ベッドの上など、写真がばらばらなほど 1〜5 が悪くなる |

**結論**: 「写真を体に合わせる」から「**体を服に合わせる**」に、「機械が推し量る」から「**登録のときに人が 1 回だけ印を付ける**」に変える。

## 2. 方針 (3 つの転換)

### 転換 A: 登録のときに 1 回だけ「型紙合わせ」をする
服をしまうとき、写真の上に**種類ごとの印 (2〜4 点)** を出し、利用者がドラッグで肩先・袖口などに合わせる。
はじめの位置は今の測り方 (`cutout.ts`・`measureSleeve` など) で置いておくので、ずれていなければ「これでよい」を押すだけ。
**一度人が確かめた印は二度と推し量らない**。着せ替えの画面はこの印だけを使うので、結果がいつも同じになる。

### 転換 B: 写真は曲げない・切らない。体のほうが服に合わせて動く
- 服の写真は**拡大縮小・回転・平行移動だけ** (2 点からの相似変換)。袖を切り分けて回すのをやめる
- **腕は袖口の向きに伸びる**。手は袖口から出る (長袖なら袖口の位置、半袖なら袖口の先へ腕の長さまで)
- **脚はズボンの裾の位置に開く**。足首は裾から出て、くつはそこに履く
- アウターを着ていれば、腕はアウターの袖に合わせる (中の袖は隠れる)

### 転換 C: アバターは「マネキン」にする (平らな写真となじむ)
写実的な 3D の体を、**顔も髪もない、のっぺりしたマネキンの平らな絵 (SVG)** に置きかえる (持ち主 2026-11-21: マネキンのイメージ・詳細は描かない)。
腕・脚・首は**部品ごとに角度と長さを変えて描く** (SVG なので 1 枚の絵を曲げる必要がない)。
細部のないマネキンなら、平らな写真を着せても「服が主役」で、着ている姿を脳が補ってくれる (店のマネキン・紙の着せ替え人形と同じ仕組み)。

### 転換 D: 最後のひと押しは、着せ替えの画面で指で直せる (持ち主 2026-11-21 の案)
自動で置いた位置が気に入らなければ、**服もマネキンも、iPhone の指の操作でずらす・傾ける・大きさを変える**ことができる (§6.1)。
印 (転換 A) が土台で、指の直しは仕上げ。印なしで指だけに頼ると、毎回直す手間になるので、両方を持つ。

## 3. 大きさのものさし: センチで決める

体も服も**センチの世界**で置く。台の上の 1 px が何 cm かは、アバターの身長 (例 160 cm) で決まる。

服は印の 2 点が**実物のどの寸法か**が種類ごとに決まっているので、それだけで写真全体の縮尺が決まる。

| 種類 | 縮尺を決める 2 点 | その実寸の目安 (アバター 160 cm) |
| --- | --- | --- |
| トップス・アウター・ワンピース | 左の肩先・右の肩先 | 肩幅 39 cm (アウターは 42 cm) |
| ボトムス | ウエストの左端・右端 (平置きの幅) | 36 cm |
| くつ | 片方の靴の幅の左右 | 9 cm |
| こもの (帽子) | つばの左右 | 写真の比で頭幅の 1.6 倍 |

こうすると、**丈は写真の縦横比から自然に出る** (ロングコートは長く、クロップド丈は短く見える)。
服同士の釣り合いは同じものさしでそろうので、「上下のバランスがどう見えるか」がイメージできる。

## 4. 種類ごとの印

| 種類 | 印 (ドラッグで合わせる) | 何に使うか |
| --- | --- | --- |
| トップス | 肩先 L/R・袖口 L/R | 肩→体の肩、袖口→腕の向きと手の位置 |
| アウター | 肩先 L/R・袖口 L/R | 同上 (中の服より優先して腕を決める) |
| ワンピース | 肩先 L/R・袖口 L/R (袖なしは省ける) | 同上。裾の下から脚が出る |
| ボトムス | ウエスト L/R・裾の真ん中 L/R (スカートは省ける) | ウエスト→体の腰、裾→脚の開きと足首 |
| くつ | 左の靴の左右・右の靴の左右 | それぞれの足に。履き口の高さは足首 |
| こもの | 置き場所 (頭・首・手) を選ぶ + 2 点 | 帽子→頭、マフラー→首、バッグ→手に持つ |

- 印の見た目は丸いつまみ (48 px 以上、`--tap`) と、何の印かの短い文字 (「左の肩」)。ルーペで指の下を拡大する
- 種類を選んだ時点で、**撮る前のカメラ/写真の上に、その種類の淡い型紙 (肩と裾の線)** を重ねて出し、「線に合わせて正面から」と添える (撮り方の手引き。床に平置き・ハンガー・ベッドのどれでもよい)

## 5. 切り抜きも登録のときに確かめる

- 登録の工程で切り抜きを作り、**利用者に見せて確かめる** (今の「切り抜けなかった写真」の知らせ #47 を、全部の写真に広げる)
- 残った背景は「消しゴム」・消えすぎた所は「戻す」でなぞって直せる (太いブラシ 1 種だけ。細かい道具は作らない)
- 確かめた切り抜きを**透明つきの WebP** にしてサーバーに送る (今の検査 `photo.ts` は WebP を受け取れる。300KB に収まる長辺に縮める)。表示のたびに切り抜き直さない
- 印の位置は、この WebP の画素に対する割合 (0〜1) で持つ

## 6. 着せる (表示の決まり)

台の上の重ね順 (下から): 脚 → くつ → ボトムス → トップス (インしないとき) → 腕 → アウター → こもの → 頭・手

| 決まり | 中身 |
| --- | --- |
| 服を置く | 印 2 点を体の対応する 2 点に重ねる相似変換 (曲げない)。体の点はセンチの表 (§3) から |
| 腕 | 肩の関節から、**一番外の服の袖口**へ向けて描く。袖口が腕の長さより先なら手は袖口に、手前なら袖口の先へ腕の長さまで伸ばす。袖なし・服なしなら少し開いた既定の角度 |
| 脚 | 股から、ボトムスの**裾の真ん中**へ向けて描く。足首は裾の下。スカート・ワンピースは既定の開き |
| くつ | 足首の位置に履き口を合わせる。ボトムスの裾より前 (今の #39 を引き継ぐ) |
| インする | トップスを着ていてボトムスもあるとき、「インする / 出す」を切り替え。インするはトップスの腰より下をボトムスの後ろに回す (保存しない、見るだけ) |
| 前を開ける | アウターは中にトップス/ワンピースがあれば、今の `OPEN_GAP` と同じく前を開ける。ただし切る位置は印の真ん中 (肩 L/R の中点の真下) から決める |
| まだ印がない服 | 推し量った印で着せ、棚のタイルに「合わせる」の印を出す。押すと型紙合わせへ |

### 6.1 指で直す (iPhone の操作が前提)

| 操作 | 服 (写真) | マネキン |
| --- | --- | --- |
| タップ | 選ぶ (細い枠とつまみが出る)。もう一度タップか台の外で外す | 選ぶ |
| 1 本指でドラッグ | ずらす | 全体をずらす。**手・足の先のつまみ**をドラッグすると腕・脚の角度が変わる |
| 2 本指でつまむ・広げる | 大きさ (0.7〜1.4 倍) | 大きさ (0.85〜1.15 倍。服との釣り合いを変える) |
| 2 本指でひねる | 傾ける (±30°) | 傾ける (±10°) |
| 「もとに戻す」 | 選んだものを自動の位置へ | 同左 |

- **直す場所を広くする**: 今日の画面の台 (200×400px) は指 2 本には小さいので、台をタップすると**全画面の「直す」モード**になる (台を画面いっぱいに。棚は下に引っ込める)。「できた」で戻る
- 重なった服は**一番上から選ぶ**。下の服を選びたいときは、選んだ状態で「うしろの服」ボタン (または 2 回目のタップで 1 枚下へ)
- 腕・脚を手で動かしたら、袖口への自動の合わせ (§6) はその服を外すまで止める
- **どこまで覚えるか: コーデごと** (持ち主 2026-11-21「服のテーブルは服の情報。直しはそれとは別であるべき」)
  - 服の直しは、そのコーデの中のその服 (`outfit_items` の行) に覚える。同じ服でも、別のコーデでは別の直し
  - マネキンの直し (大きさ・傾き・腕と脚の角度) も、そのコーデ (`outfits` の行) に覚える
  - 「これに決めた」までは画面の中だけで持ち、決めたときにコーデと一緒に保存する。決め直し (新しいものを足してから前のものを消す) でも直しを引き継ぐ
  - 新しいコーデで服を着せると、直しのない自動の位置 (印から) から始まる。カレンダーの下見・似た日のコーデは、保存した直しのまま出す
- iOS の Safari の決まり: 台は `touch-action: none` (ページのスクロール・拡大と取り合わない)、`gesturestart` を止める (Safari の画面の拡大)、`-webkit-touch-callout: none` と `user-select: none` (長押しで画像の保存メニューを出さない)。Pointer Events だけで書き、外のライブラリは使わない
- 読み上げ・キーボードでも直せるように、選んだものに「左へ・右へ・上へ・下へ・大きく・小さく・左に傾ける・右に傾ける」のボタンを出す (少しずつ動く)

**難しさの見立て**
| 部分 | 難しさ | 理由 |
| --- | --- | --- |
| 服のずらす・大きさ・傾ける | 低〜中 | 2 本の指の位置から移動・倍率・角度を出す計算は小さな純粋な関数 (テストしやすい)。依存は足さない |
| 全画面の「直す」モード | 低 | 台の大きさを変えるだけ。位置はセンチの世界 (§3) で持つので、台の大きさが変わってもずれない |
| マネキンの腕・脚のつまみ | 中 | 腕・脚はもともと角度で描く部品 (§7) なので、つまみの位置から角度を出すだけ。袖口への自動の合わせとの取り合いを決める必要がある |
| 重なった服の選び分け | 中 | 透明な部分をタップしても下の服を選べるよう、写真の画素の透明さで当たりを判定する |
| e2e で 2 本指 | 中 | Playwright の Chromium に CDP の `Input.dispatchTouchEvent` で 2 本の指を送る。iPhone の実機の手ざわりは持ち主が確かめる |

まとめると、**1 版ぶんで収まる大きさ**。ただし土台 (印とマネキン) が先。土台の上で直すから少し動かすだけで済み、土台がないまま指の直しを先に作ると毎回大きく直すことになる。

## 7. アバター (マネキン)

- **マネキンの平らな絵 (SVG、repo の中で描く)**。頭 (卵の形)・首・胴・上腕/前腕/手・腿/すね/足を部品に分ける。外の素材は使わない
- **詳細は描かない**: 顔・髪・指・筋肉・肌の陰影なし。1 色の面と、関節の継ぎ目の細い線だけ。色はテーマに合わせた淡い 1 色 (服の色を邪魔しない)
- 服を着ていないところもマネキンの地のままなので、下着姿にはならない (#28 の意図はこれで満たす)
- 立ち方は正面・腕を少し開いて下ろす (ハンガーの袖の垂れ方に近い)
- 体型 (身長・肩幅・腰幅の 3 段) は**端末の localStorage にだけ置く**。サーバーに送らない (DATA.md に足す)。指の直し (§6.1) はコーデに覚える (§8)
- 台の大きさ (`--stage-w` × `--stage-h`) と、今日の画面の 2 列のつくり (design-system.md) はそのまま

## 8. データ (変えるもの・変えないもの)

**変えたい (人に頼む: migrations は守りの部分)**
- `clothes` に **`fit` を 1 欄** (TEXT、zod で検査した数だけの JSON。例 `{"v":1,"p":[[0.21,0.08],[0.79,0.08],[0.05,0.62],[0.95,0.61]],"at":"head","adj":[0.5,-1.2,1.05,-4]}`。点は 6 個まで・0〜1、置き場所は決まった語だけ、200 文字まで)。**服そのものの情報 (どこが肩か) だけ**を持つ
- `outfit_items` に **`adj` を 1 欄** (TEXT、JSON。例 `[0.5,-1.2,1.05,-4]` = ずらす cm 横・縦、倍率 0.7〜1.4、角度 ±30°。null なら直しなし)
- `outfits` に **`pose` を 1 欄** (TEXT、JSON。例 `{"s":1.05,"r":-3,"dx":0,"dy":0,"arm":[28,null],"leg":[null,null]}` = マネキンの倍率 0.85〜1.15・角度 ±10°・ずらす cm・腕と脚の角度 (null は自動)。null なら直しなし)
- API: `POST /api/outfits` の `itemIds` を `items: [{id, adj}]` に、`pose` を足す (zod で範囲を検査。古い形 `itemIds` もしばらく受け取る)。書き出し (JSON) にも入れる
- 個人の情報は増えない (写真の中の割合・cm・倍率・角度の数だけ)。DATA.md の `clothes`・`outfits`・`outfit_items` の行に足す

**変えない**
- 写真の検査 (`photo.ts`)・ログイン・セッション・天気・おすすめ・カレンダー・コーデの保存
- 服の種類 6 つ・暖かさ・ラベル

**この欄が認められなかったときの代わり** (推奨しない): 印に合わせて写真を決まった枠に焼き込み (肩を枠の決まった位置に)、袖口は透明の画素から測る。表示は決まるが、袖口だけはまた推し量りになる。

## 11. 受け入れ条件 (合格の見方)

**目で見る基準 (持ち主が確かめる)**
- 持ち主の「例の写真」と、撮り方の違う写真 (ハンガー・床の平置き・ベッドの上・少し斜め) で、型紙合わせをしたあと
  - 服の肩が体の肩に乗っている
  - 手が袖口から、足がズボンの裾から出ている (浮いた手・服を突き抜けた腕がない)
  - 服の後ろに背景の四角が残っていない
  - トップス + ボトムス + アウター + くつを着たとき、**ひとりの人が着ているように見える** (持ち主が「イメージがわく」と言えるか)

**テスト (AC ごとに `AC-<issue>-<n>`)**
- 相似変換: 印 2 点が体の 2 点にぴったり重なる (全件ループ・PBT。誤差 0.5 px 以内)
- 写真の縦横比が変わらない (曲げない) ことを PBT で
- 腕: 手の位置が袖口 (長袖) / 腕の長さ (半袖) になる境界値
- 脚: 裾の真ん中に足首が来る。スカートは既定の開き
- `fit` の zod: 範囲外・点の数の超過・知らない置き場所を拒む。fuzz
- 認可: 別の利用者の服の `fit` を読めない・変えられない (`worker.test.ts` の形)
- e2e: 見本の写真で登録 → 型紙合わせ (つまみをドラッグ) → 今日の画面で着た姿のスクリーンショット。**見た目の基準画像**と比べる
- 指の直し: 2 本の指の動きから移動・倍率・角度を出す関数を PBT で (指を入れかえても同じ・範囲の端で止まる)。e2e で「直す」モードに入り、2 本指で広げると服が大きくなり、「これに決めた」のあと開き直しても同じ位置 (`outfit_items.adj`)。同じ服を別のコーデで着せると自動の位置 (直しがコーデをまたがない)
- `adj`・`pose` の zod: 範囲外・数の超過を拒む。fuzz。認可: 別の利用者のコーデの直しを読めない・変えられない
